# シーン遷移システム設計書

## 1. 概要
ドラクエ7や8のような、ワールドマップ、街、城、ダンジョン、屋内をシームレス（またはフェードを挟んで）移動するためのシステム構成案です。
多様なエリアが存在する広大な世界に対応するため、データ駆動型の設計を採用します。

## 2. システム構成案

### 2.1 状態管理 (Zustand: `gameStore.js`)
現在の `useGameStore` に以下の要素を追加します。

- `currentMapId`: 現在滞在しているマップのID。
- `previousMapId`: 遷移前のマップID（スポーンポイントの決定に使用）。
- `isTransitioning`: 遷移演出中（フェード中など）かどうかのフラグ。
- `spawnPointId`: 次のマップで出現する地点のID。

### 2.2 マップデータ構造 (`src/data/maps/`)
既存の `map.schema.js` を拡張し、以下の情報を管理します。

- `MapType`: `WORLD_MAP`, `TOWN`, `DUNGEON`, `INTERIOR` などの区分。
- `connections`: 隣接するマップへの接続情報。
    - `targetMapId`: 遷移先マップ。
    - `triggerZone`: 遷移を発生させる空間領域（AABBなど）。
    - `spawnPointId`: 遷移先での出現地点。
- `spawnPoints`: マップ内の出現可能地点のリスト。

### 2.3 技術スタックと実装方針
- **React Three Fiber (R3F)**: 3Dレンダリング。
- **Suspense**: マップアセット（GLB）の動的ロード。
- **Zustand**: 前述の状態管理。
- **Spatial Triggers**: プレイヤーの位置を `useFrame` で監視し、`triggerZone` に入った瞬間に遷移処理を開始。

## 3. シーン遷移の流れ

1. **トリガー検知**: プレイヤーが街の入り口や建物のドア（トリガー領域）に接触。
2. **遷移開始**: 
    - `isTransitioning` を `true` に設定。
    - UIレイヤーでフェードアウト演出を開始。
3. **データ更新**: 
    - 演出のピーク時に `currentMapId` を更新。
    - `spawnPointId` に基づきプレイヤーの座標を初期化。
4. **アセットロード**: 
    - Reactの `Suspense` により、新しいマップのGLBモデルを非同期ロード。
5. **遷移完了**: 
    - モデルのロード完了後、`isTransitioning` を `false` に戻す。
    - フェードイン演出を開始。

## 4. 詳細実装計画

### フェーズ1: 基礎基盤の実装
- `gameStore` へのマップ遷移状態の追加。
- `World` コンポーネントの動的マップ読み込み化。
- `FadeTransition` UIコンポーネントの作成。

### フェーズ2: トリガーシステム
- 各マップ定義に基づいた `TransitionTrigger` コンポーネントの自動配置。
- 衝突判定、または近接判定による遷移発火。

### フェーズ3: 大規模マップへの対応
- ワールドマップとローカルマップでの解像度/表示距離の切り替え。
- 必要に応じたテクスチャのLOD設定。

## 5. データのスケーラビリティについて
シナリオドラフトにある「七つの大地」に対応するため、各エリア（Area 1, Area 2...）ごとにデータファイルを分割（`src/data/maps/area1.js`, `area2.js` ...）し、メインのインデックスファイルで統合することで、メンテナンス性を高めます。
